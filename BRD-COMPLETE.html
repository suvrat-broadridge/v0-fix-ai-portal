Executive Summary

B-COMET (Configuration Onboarding Monitoring Evaluation and Tracking) is a role-based platform designed to streamline client FIX protocol implementations across multiple asset classes and FIX protocol versions.

Core Value Proposition: Reduce onboarding cycle time by 30%, improve implementation quality, and provide complete operational transparency for both internal teams and client users.

Platform Overview

B-COMET provides end-to-end workflow coverage including:

  • FIX specification onboarding and comparison
  • Log analysis and issue tracking
  • Scenario creation and test generation
  • Certification support workflows
  • ATDL (Algorithmic Trading Definition Language) tooling
  • FIX Message Creator utility
  • Real-time progress tracking and alerting

Business Problem Statement

Current FIX onboarding and certification activities are fragmented and inefficient:

Manual Fragmentation

Tools and processes scattered across manual files, email threads, and ad-hoc trackers

Longer Timelines

Extended client onboarding cycles due to lack of unified workflow management

Inconsistent Outcomes

Validation and comparison results vary based on manual execution

Limited Visibility

No real-time view into client progress, blockers, or pending tasks

SME Dependency

High reliance on specialized experts for repetitive tasks

Increased Risk

Operational and certification risks due to lack of standardization

Key Objectives

  • Reduce end-to-end client FIX onboarding and validation cycle time by at least 30%
  • Improve first-pass accuracy of FIX specification alignment
  • Provide a single operational view of progress by client, asset class, and protocol version

Scope Definition

In Scope

  • Role selection and login flow (Admin and Client personas)
  • Admin and Client dashboard views with portfolio metrics and progress tracking
  • Client management workflows for admin users
  • Spec management: upload, comparison, and standardized conversion
  • Log analysis workflow with issue classification and tracking
  • Scenario creation and test case generation (Regression and Certification)
  • FIX Message Creator utility
  • ATDL tooling workflows (compare, convert, validate, usage representation)
  • Settings and administration modules
  • Backend connectivity visibility and health checks

Out of Scope (Initial Release)

  • Full enterprise IAM/SSO integration (SAML/OIDC)
  • Production billing and subscription management
  • End-user self-service tenant provisioning
  • Complex entitlement hierarchy beyond role-based access
  • Advanced audit/compliance requirements
  • AI/ML recommendations beyond workflow support

User Personas

Admin User

Primary Goals:
  • Manage client onboarding lifecycle efficiently
  • Track progress across multiple clients and asset classes
  • Execute advanced tooling workflows (spec comparison, test generation, certification)
  • Identify and resolve blockers quickly

Responsibilities: Oversees client onboarding, spec comparison, progress tracking, task coordination, and certification workflows.

Client User

Primary Goals:
  • Understand own implementation progress clearly
  • View assigned tasks and deliverables
  • Execute allowed workflows with clear guidance
  • Get quick feedback on specification alignment

Responsibilities: Tracks onboarding progress, reviews specifications, uses tools like spec comparison overview, log analysis, and ATDL validation.

Functional Requirements

Core Authentication & Access

Requirement ID Description
FR-01 Role-based Access: System shall support Admin and Client roles with role-appropriate navigation, data, and actions
FR-02 Authentication: System shall provide login experience for each role and validate backend availability

Dashboard & Visibility

Requirement ID Description
FR-03 Dashboard: Admin dashboard displays portfolio metrics, pending tasks, and alerts. Client dashboard shows progress by asset class
FR-16 Alerts & Notifications: System shall display alert counts and status indicators throughout key workflows

Client & Spec Management

Requirement ID Description
FR-04 Client Management: Admins shall create clients with metadata (name, identifier, asset classes)
FR-05 Client Details: Show per-client status by asset class and version with direct tool navigation
FR-06 Spec Management: Support listing, uploading, and version selection of client and admin specs
FR-07 Conversion: Call backend conversion endpoints for spec standardization with error handling

Workflow Tools

Requirement ID Description
FR-08 Spec Comparison: Compare client and admin specs with multi-spec visibility and difference tracking
FR-09 Log Analysis: Allow users to run log analysis and classify findings with status tracking
FR-10 Scenario Creation: Support creation and management of test scenarios
FR-11 Regression Tests: Convert scenarios into regression test case outputs
FR-12 Certification Tests: Generate certification-oriented test cases
FR-13 FIX Message Creator: Support field editing, sequencing, and send/receive log viewing
FR-14 ATDL Workflows: Compare, convert, validate, and represent ATDL-related functionality
FR-15 Settings: Configurable settings for general, look and feel, security, mail, questionnaires, and license

Non-Functional Requirements

Requirement ID Description
NFR-01 Availability: Target 99.9% monthly uptime in production
NFR-02 Performance: Page interactions responsive under load; health checks within acceptable thresholds
NFR-03 Security: Role-based access enforcement, secure token handling, and protection against unauthorized access
NFR-04 Data Integrity: Changes to comparisons, test states, and workflow events shall be traceable
NFR-05 Scalability: Support growing client volume, asset classes, and parallel onboarding activities
NFR-06 Usability: Clear status signals, guided workflow progression, minimal training overhead
NFR-07 Maintainability: Modular architecture supporting expansion of tools and endpoints

Core User Workflows

Workflow 1: Client Onboarding & Progress Tracking

1
Admin selects or creates a new client with metadata
2
System initializes client record with asset class and FIX version context
3
Admin/Client views dashboard showing progress by asset class
4
System reflects updated progress, alerts, and pending actions in real-time

Workflow 2: Specification Comparison

1
User uploads or selects client FIX specification file
2
System calls backend conversion endpoint to standardize spec format
3
System compares client spec against admin reference specification
4
User reviews differences, flags issues, and marks comparisons complete

Workflow 3: Log Analysis & Issue Tracking

1
User uploads FIX protocol log file for analysis
2
System processes log and classifies findings (errors, warnings, compliance issues)
3
User reviews identified issues and assigns status/notes
4
System tracks resolution progress and updates client status

Workflow 4: Test Generation & Certification

1
Admin creates test scenarios for client FIX implementation
2
System converts scenarios into test case format (regression or certification)
3
System generates test cases aligned with certification requirements
4
User executes tests, tracks results, and updates certification status

Integrations & Dependencies

Backend Services Required

  • Authentication API: User login and session management
  • Platform Data API: Client, spec, and progress data management
  • Conversion Runner: Spec standardization and format conversion
  • Log Analysis Service: FIX log processing and issue classification
  • Test Generation Service: Scenario-to-test conversion and test case generation
  • Comparison Engine: Specification and ATDL comparison workflows

External Tool Integrations

  • VeriFIX: Regression test case generation and validation
  • Conductor: Certification workflow orchestration
  • ATDL Tools: Algorithm trading definition parsing and validation

Infrastructure

  • PostgreSQL or compatible relational database
  • Redis for caching and session storage (optional)
  • WebSocket services for real-time progress updates (optional)
  • File storage system for specs and logs

Assumptions & Constraints

Assumptions

  • Admin and Client roles are sufficient for initial go-live
  • Backend services required for full mode are available in production environments
  • Conversion runner and token-based control are managed securely by operations
  • Product and business teams will finalize process ownership for each workflow stage
  • API contracts and data formats will be standardized before development

Constraints

  • Prototype contains simulated or placeholder data in selected flows
  • Some workflows rely on backend availability and environment configuration
  • Production controls for data governance, audit, and compliance may require additional scope
  • Frontend and backend development must proceed in parallel with clear API contracts
  • User training and documentation must be prepared before go-live

Risks & Mitigations

Risk Impact Mitigation
Prototype-to-production gaps in data persistence and validation High Define MVP acceptance criteria and UAT checkpoints per module
Dependency on local runner tooling creates environment inconsistencies Medium Standardize runtime profiles and deployment runbooks
Role and entitlement requirements may expand after pilot Medium Add entitlement extensibility in access-control design
Incomplete audit/compliance capabilities at first release High Plan phase-2 compliance controls with security stakeholders
Backend service unavailability impacts all workflows High Implement graceful degradation and offline mode where possible
User adoption slower than expected Medium Plan comprehensive training program and in-app guidance

MVP Definition

Minimum Viable Product Scope:

The MVP focuses on core workflows that directly impact onboarding cycle time reduction and operational visibility.

Included in MVP

  • Authentication & Access Control
    • Role-based login for Admin and Client roles
    • Session management and logout functionality
  • Dashboards
    • Admin portfolio overview with metrics and task visibility
    • Client progress dashboard by asset class
  • Client Management
    • Create and manage clients
    • Track client details and asset class assignments
  • Specification Workflows
    • Upload and manage client specs
    • Standardized conversion integration
    • Spec comparison (basic)
  • Log Analysis (Baseline)
    • Log upload and processing
    • Issue classification and tracking
  • Test & Certification Shells
    • Scenario creation interface
    • Test generation workflow entry points
  • ATDL Entry Points
    • ATDL comparison basic workflow
    • ATDL validation interface
  • Settings & Configuration
    • General platform settings
    • User preferences

Not Included in MVP (Phase 2+)

  • Advanced analytics and reporting
  • Enterprise IAM/SSO integration
  • Full audit and compliance controls
  • Advanced ML/AI recommendations
  • Multi-tenant self-service provisioning

Acceptance Criteria

Business-Level Acceptance Criteria

  • Admin User Journey: Admin users can successfully onboard new clients, assign asset classes and FIX versions, track progress, and access all core tools
  • Client User Journey: Client users can view own status, navigate assigned specs, access log analysis and ATDL tools, and track pending tasks
  • Spec Workflows: Spec conversion and comparison flows operate with clear success/failure feedback and proper error messaging
  • Status Visibility: Onboarding status is visible at both dashboard and detail levels with meaningful progress indicators
  • Performance: Page loads within 3 seconds and API responses under 500ms for 95th percentile
  • Operational Reporting: Business stakeholders can generate weekly progress reports from platform data

Technical Acceptance Criteria

  • All functional requirements (FR-01 through FR-16) implemented and tested
  • All non-functional requirements (NFR-01 through NFR-07) met or documented
  • Backend API contracts finalized and documented
  • Unit test coverage ≥ 80% for critical paths
  • UAT testing completed with stakeholder sign-off
  • Production deployment runbook completed and tested

Implementation Timeline

Phase 1: MVP (Q2 2026)

Duration: 8 weeks | Objective: Launch core platform with essential workflows

  • Weeks 1-2: Backend API development and database schema
  • Weeks 2-4: Frontend implementation (auth, dashboards, client management)
  • Weeks 4-6: Workflow implementation (spec, log analysis, test shells)
  • Weeks 6-7: Integration testing and bug fixes
  • Week 8: UAT and production deployment

Phase 2: Enhanced Workflows (Q3 2026)

Duration: 6 weeks | Objective: Deepen workflow automation and add advanced features

  • Advanced spec comparison with multi-version support
  • Enhanced test generation with VeriFIX and Conductor integration
  • ATDL workflow completion
  • Audit and compliance controls (phase 1)

Phase 3: Platform Hardening (Q4 2026)

Duration: 8 weeks | Objective: Enterprise scale and optimization

  • Enterprise IAM/SSO integration
  • Advanced analytics and reporting
  • Performance optimization
  • Full compliance controls and audit trails
  • Multi-language support
